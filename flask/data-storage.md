# Хранение данных
Где и как можно хранить данные во Flask без базы данных.

Если мы хотим **хранить данные без базы данных**, то у нас есть несколько временных (но вполне рабочих) способов. Давай разберём по порядку:

---

## 🧠 Варианты хранения данных во Flask **без базы данных**

### 1. 🗂️ **Временное хранение в переменной (списке)**

Это самый простой способ — **данные живут в оперативной памяти**, пока Flask не перезапущен.

```python
posts = []  # Глобальный список

@app.route("/add", methods=["POST"])
def add():
    title = request.form["title"]
    posts.append(title)
    return redirect("/blog")
```

✅ Просто.
❌ Улетит при перезагрузке. Не для продакшна, но идеально для начала и отладки.

---

### 2. 🧺 **session** — хранение данных на стороне клиента (в cookies)

```python
from flask import session

app.secret_key = "секретный ключ"

@app.route("/setname", methods=["POST"])
def setname():
    session["name"] = request.form["name"]
    return redirect("/")

@app.route("/")
def index():
    name = session.get("name", "Гость")
    return f"Привет, {name}"
```

✅ Данные хранятся **между перезапусками сервера** (в cookies).
❌ Лимит объёма (обычно до 4 КБ), всё хранится у пользователя.

---

### 3. ✉️ **flash** — для временных сообщений

```python
from flask import flash, get_flashed_messages

flash("Пост добавлен!")
messages = get_flashed_messages()
```

✅ Удобно для уведомлений ("успешно добавлено!", "ошибка входа")
❌ Нельзя использовать для хранения постов и постоянных данных

---

### 4. 📁 **Файл (JSON / CSV)**

Если хочешь «псевдо-БД» — можно писать и читать из файла:

```python
import json

def save_post(title):
    with open("posts.json", "r") as f:
        data = json.load(f)
    data.append({"title": title})
    with open("posts.json", "w") as f:
        json.dump(data, f)
```

✅ Не потеряется при перезапуске.
❌ Медленно, может ломаться при одновременной записи.

---

## 💡 Вывод

| Метод     | Для чего подойдёт           | Постоянство |
| --------- | --------------------------- | ----------- |
| Список    | Локальная отладка, черновик | ❌           |
| `session` | Настройки пользователя      | 🔸          |
| `flash`   | Уведомления (одноразовые)   | ❌           |
| Файл      | Простая "БД" без БД         | ✅           |

## 🧭 Когда изучать `session` и `flash` во Flask?

Они нужны не на старте, а чуть позже — когда **начинаем делать взаимодействие с пользователем**. Вот как я предлагаю распределить:

---

## 📌 План этапов обучения Flask

### **1. Маршруты, GET/POST, шаблоны (уже делаем ✅)**

👈 Это база. Просто страницы, формы, вывод данных.

---

### **2. Создание блога:**

* Добавление постов (из формы)
* Хранение в памяти
* Вывод списка на странице через Jinja2
  📌 **Сюда мы идём сейчас**

---

### **3. Использование `session`**

🧠 Когда пригодится:

* Хранить **имя пользователя** после логина
* Показывать "Добро пожаловать, Даян!"
* Упрощённая авторизация (до того как подключим БД)

📅 Можем изучить после блога — **как только появляется взаимодействие с пользователем**
➡️ Пример: “Введите имя один раз — и мы его запомним”

---

### **4. Использование `flash`**

💡 Где нужен:

* Сообщения типа “Пост успешно добавлен!”

* “Комментарий отправлен”

📅 Лучше всего — **перед созданием полноценной формы обратной связи или авторизации**

## А когда JSON
Вот это стратегический подход, Даян! 💪
Ты прав — **хранение в JSON** действительно логично встает **между списками и сессиями**, особенно если мы хотим данные сохранять **между перезапусками сервера**.

---

## 📊 Как JSON вписывается в наш путь:

### 🔢 1. **Список в памяти**

* Посты хранятся в `posts = []`
* Простейший способ, но данные теряются при перезапуске

⬇️

### 📁 2. **JSON-файл**

* Всё то же, но сохраняется в файл
* Данные остаются после перезапуска сервера
* Почти как “ручная база данных”
* Нет зависимости от SQL и БД — просто читаем/пишем в файл

⬇️

### 🧠 3. **Сессии (`session`)**

* Храним небольшие персональные данные (например, имя пользователя)
* Данные живут в браузере пользователя (в cookies)

⬇️

### ✉️ 4. **Flash-сообщения**

* Уже более “UI-фишка” — добавим, когда будет авторизация или формы

⬇️

### 🧰 5. **Настоящая БД (например, SQLite)**

* Когда надо хранить много данных, делать поиск, фильтрацию и т.д.

---

## 🔥 Идеальный порядок для нашего проекта:

| Этап | Что изучаем               | Что реализуем в проекте                 |
| ---- | ------------------------- | --------------------------------------- |
| 1️⃣  | Список `posts = []`       | Блог, который работает, пока сервер жив |
| 2️⃣  | Хранение постов в JSON    | Посты сохраняются между запусками       |
| 3️⃣  | `session`                 | Запоминаем имя пользователя             |
| 4️⃣  | `flash`                   | Показываем сообщения после действий     |
| 5️⃣  | SQLite/SQLAlchemy (позже) | Настоящая БД для постов и пользователей |

---

❌ Не масштабируется на больших проектах
❌ Может глючить при параллельной записи
